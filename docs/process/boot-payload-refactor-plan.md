# 启动载荷与测试环境解耦计划

## 目标与范围

基础启动环境以独立 `initrd.cpio` 交付，包含 `conf/task.conf`、非测试
模块、用户 ELF 和必需数据。测试环境使用独立的 `test*.conf` 与载荷集合。
Limine 是交付方式之一，可以同时交付基础归档与测试文件；载荷用途不能
由引导器名称决定。内核通过自身接口处理文件、配置和执行。

本轮只在 x86_64 实施阶段 1～3，不 rebase ARM64/main、不推送、不切换
归档交付方式，不迁移运行期测试模块。现有 Limine 混合 task.conf 暂时通过
明确标注的兼容上下文运行；正常/测试/救援模式的最终选择入口留到后续阶段。

## 启动契约

- 基础、测试、救援、兼容配置分别拥有文件集合、任务、指令和执行状态。
- 基础配置不接受 `@test`；测试只在显式测试或兼容上下文中启用。
- 配置只在所属集合查找组件，使用规范化完整路径精确匹配；不进行隐式
  跨集合回退，不在解析失败后改用另一个配置。
- 两个集合可具有同名文件；一个集合内的同路径文件视为歧义并拒绝使用。
- 文件视图借用来源内存。调用者须保持描述符、路径和载荷有效，直到全部
  消费者停止使用。引导器内存回收和模块卸载不属于本轮范围。
- 配置解析失败后清理部分任务及指令；同一配置不可重复解析，同一 CPU
  不可重复提交其任务。已经开始执行的配置不允许销毁或重新初始化。
- 任务入队不等于服务就绪。后续阶段必须按实际依赖建立就绪条件。
- 早期状态性测试在真实设备注册前执行；破坏性测试使用专门启动场景。

## 分阶段交付

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| 1 | 确定用途、来源、错误策略和阶段依赖 | 契约及迁移边界记录到文档 |
| 2 | 实例化配置上下文，分离任务/指令/策略/执行状态 | 两份配置可独立解析，失败清理，防止重复执行 |
| 3 | 建立引导器无关的文件视图及集合，接入模块列表和 CPIO | 精确查找、无隐式回退、独立归档不干扰，任务和测试加载共用接口 |
| 4 | 打包独立 initrd，校验配置引用完整性 | 基础配置及全部组件进入可独立检查的归档 |
| 5 | 接通基础配置启动，替换手工 initrd 用户程序路径 | 私有页表、实际入队、退出及加载失败清理均验证 |
| 6 | 拆分 test*.conf，建立显式测试模式 | 普通启动不加载测试配置，两个阶段不相互替代 |
| 7 | 分批迁移 priority/remote_enqueue/RCU 等运行期测试 | 保留前置条件、完成判据、超时和清理；早期测试及特殊 ELF 例外保留 |
| 8 | 完善多模式构建和 CI | 正常、专项、预期异常分别有门禁与日志 |

## 验证策略

阶段 1～3 的宿主测试直接编译真实文件接口、配置管理器和解析器，验证
来源隔离、CPIO 游标隔离、路径歧义、解析失败清理、用途限制和分配失败。
x86_64 QEMU 门禁覆盖既有配置的正常启动、任务参数、多用户及模块加载失败。
测试不能只检查源码文本或把内核启动标志当作全部配置成功。

后续补充：基础归档独立启动、无测试载荷启动、显式测试模式、同名组件隔离、
服务就绪依赖、不同引导器交接。ARM64 直启可在迁移期间保留内嵌归档，最终
转换成同一种内部文件集合；外置归档交接单独实施。

### 阶段 7：四项运行期测试迁为载荷

2026-10-27 将 priority、remote_enqueue、rcu_publish 和 rcu_stress 从
`kernel/tests/` 移至 `module/tests/`，删除旧头文件和内核注册调用，分别以
`selftest_init()` 注册。测试配置显式填写 `module=`，测试/兼容镜像列出载荷；
基础归档和正常镜像不包含它们。早期状态性测试和 registry 自检保留内置。

保留原有 worker、配置、超时及完成判据；priority 准备失败时补齐未入队
worker 的回收。新增所需公共操作和 RCU 状态/指标导出，要求模块与内核的头文件、
布局及特性配置匹配，不承诺稳定 ABI 或卸载。回调及指标仍借用模块存储，结果
报告不释放模块；运行期超时也不是通用 worker 取消机制。

新增产物符号检查和缺失载荷 QEMU 门禁，防止仅改配置却继续运行内置实现。

200/200 轮、被切出读者和空链表断言已在模块路径通过。ARM64/main 尚未同步；
后续阶段 8 完善多模式及预期异常门禁，进一步迁移 registry 等测试可独立评估。

### 阶段 8：多模式构建与 CI 门禁
