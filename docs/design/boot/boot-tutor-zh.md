# 启动教程

英文原文：[Boot tutorial](boot-tutor.md)。

引导程序提供可执行的 CPU 状态与机器描述，内核据此建立内存所有权、中断处理和可调度任务。本文沿当前 x86_64 实现阅读，接口约束见 [启动架构](boot-arch-zh.md)。

## 1. 定位实际入口

从 `kernel/arch/x86_64/main.c` 中的 `kmain()` 开始，阅读其上方静态 Limine 请求，再检查 `check_bootloader()`。各请求具有独立响应指针，因此内核无须接收常规 C 参数即可访问内存映射。

Limine 已建立支持执行的映射，但 LaOS 尚未建立自己的分配策略。可访问 RAM 不等于可以分配该 RAM。

## 2. 分析首次可用分配

```text
Limine HHDM 响应 -> hhdm_init
Limine 内存映射   -> boot_info_from_limine -> pmm_init_from_memmap
                                          -> vmm_init -> kheap_init
```

PMM 用位图跟踪物理页，VMM 管理虚拟映射，堆随后提供小粒度分配。修改顺序前应阅读 [内存教程](../memory/memory-tutor-zh.md)。

`phys_to_virt()` 加上直接映射偏移，不分配页面或建立映射。`virt_to_phys()` 仅反向转换直接映射地址，不能用于任意内核指针。

## 3. 建立中断处理条件

早期 GS 与 GDT/TSS 建立每 CPU 及栈状态，IDT 提供入口，LAPIC 和 I/O APIC 决定中断源如何到达入口。这些职责应分别核对。

从 `kmain()` 最后启用中断的 `sti` 向前检查依赖，再比较 AP 入口。各 CPU 均需完成本地状态初始化后才能安全启用中断。

## 4. 区分构造与执行

`task_init()` 读取配置并构造任务记录，`task_run()` 在当前 CPU 释放任务后返回。调度由显式调用和中断返回抢占进入，不是单个不返回的 `task_run()` 循环。

自测试也有注册、配置与执行阶段。注册表存在某项不表示它已经成功完成。

## 5. 观察普通启动

按 [入门指南](../../getting-started.md)准备环境后，从仓库根目录运行：

```sh
make test-x86_64
```

阅读目标报告的串口日志，定位页表根切换、CPU 上线、自测试结果及运行标志。AP 并发执行，消息顺序可以变化。

内核持续运行，因此目标接受 QEMU 超时退出，但仍要求具体日志标志。超时本身既不表示通过，也不能定位最后成功的初始化步骤。

## 6. 练习：说明初始化依赖

选择 PMM 与堆、每 CPU 设置与调度、或 PCI 枚举与 e1000 初始化中的一组，找到消费者首次访问生产者状态的位置，说明颠倒顺序后缺失的状态。先完成源码分析，再考虑修改启动顺序。

## 7. 练习：分类启动证据

选择一次普通启动日志，将每条标志分类为引导程序契约、内存所有权、AP 上线、设备发现、任务构造或最终运行。说明哪些标志是下一阶段的前提，哪些只是可选进展观察。
