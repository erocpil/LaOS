# 中断架构

英文原文：[Interrupt architecture](interrupt-arch.md)。

## 适用范围

x86_64 入口将硬件异常、设备 IRQ 和 IPI 转换为结构化 C 调用，返回路径同时提供抢占调度点。syscall 使用独立入口和保存帧，见 [用户态架构](../user/user-arch-zh.md)。

## 入口与保存帧约束

部分异常由硬件压入错误码，其他异常由桩补零，随后加入向量号。`PUSH_ALL` 保存通用寄存器，使内存布局匹配 `struct interrupt_frame`：

```text
低地址：rax ... r15 | int_no | error_code | rip | cs | rflags | rsp | ss
```

汇编与 C 必须保持顺序一致。公共入口按保存的 CS 判断是否来自用户态，并执行相应 GS 转换，最后恢复上下文并通过 `iretq` 返回。

syscall 的 `trap_frame` 布局不同，没有向量和错误码，不能传给要求中断帧的处理程序。

## 栈所有权

用户态中断通过 TSS 状态选择内核栈；中断内核执行的普通 IRQ 留在当前线程内核栈。致命异常门可选择专用 IST 栈。

每 CPU IRQ 栈已分配，但普通 IRQ 路径不将保存帧迁移到这些栈。挂起的中断续执行上下文必须附属于原线程，直至恢复；多个挂起线程复用同一 CPU 栈会覆盖保存帧。

详细 IST 与诊断输出见 [异常说明](../diagnostics/exception-handler.md)。

## 分发与确认

`idt_handler()` 在普通异常及 IRQ 分流之前处理 IPI：

| 来源 | 操作 |
| --- | --- |
| TLB IPI | EOI、本地 TLB 刷新及观察回调 |
| 自测试 IPI | EOI 及自测试回调 |
| 重调度 IPI | EOI 与确认，公共返回检查待处理请求 |
| 缺页异常 | 尝试用户按需分页，否则诊断或终止 |
| 定时器向量 32 | 定时器处理及 CPU tick 统计 |
| 键盘向量 33 | 输入处理 |
| 已缓存 e1000 向量 | 调用已加载驱动回调 |

CPU 异常不需要 APIC EOI。设备中断中，清除设备原因与确认 APIC 是不同操作。e1000 回调读取设备原因寄存器，公共 IRQ 路径确认 APIC。

因此确认时序是：

```text
进入向量 -> 保存帧 -> 识别来源
         -> 处理/清除设备或 IPI 原因
         -> 在需要时确认中断控制器
         -> 若有待处理请求则请求重调度
         -> 恢复被中断帧
```

未清除电平触发设备原因就发送 EOI，可能导致中断重新触发；清除设备原因却不发送控制器 EOI，则可能使控制器保持待处理状态。这是两类不同的故障，应分别定位。

## 抢占与远程任务

公共返回恢复保存帧之前检查 `need_resched`。只有当前上下文允许抢占时才进入调度，自旋锁和抢占状态参与这一判断。

远程入队先发布队列状态，再请求重调度。本地请求设置同一标志，但不向自身发送 IPI。x86_64 远程路径当前采用广播，因为逻辑 CPU 编号尚未提供通用 LAPIC ID 反向映射。

返回路径有严格顺序：处理程序可以设置 `need_resched`，但在当前中断续执行上下文保存之前，调度不能覆盖保存帧。上下文切换改变保存帧所属线程，不会将中断帧复制到共享 CPU 栈。

## 架构与所有权边界

| 项目 | x86_64 | ARM64 |
| --- | --- | --- |
| 保存帧 | `struct interrupt_frame`，通过 `iretq` 返回 | 由异常级别/架构入口管理的异常帧 |
| 设备确认 | 处理设备原因后发送 APIC EOI | 处理来源后走 GIC 确认/EOI 路径 |
| 重调度通知 | LAPIC IPI 或本地标志 | 定向 SGI 或本地标志 |
| 普通 IRQ 栈 | 被中断线程的内核栈 | 遵循异常入口及被中断上下文的架构栈规则 |

共享调度器和设备回调不能消除这些入口差异。修改保存帧布局、向量路由或 EOI 顺序时，必须分别运行对应架构验证。

## 验证与限制

```sh
make test-x86_64
make test-x86_64-smp-tlb
make test-x86_64-sched-stress
```

这些目标覆盖普通启动、命名 IPI 测试、远程入队与调度压力，不验证任意中断亲和性、CPU 热插拔或通用驱动注册框架。致命异常注入会停止内核，结果须与普通启动测试分别解释。

验证时应区分四项结论：保存帧恢复、控制器确认、设备原因处理和重调度投递。IPI 测试通过不能证明 e1000 原因路径；e1000 IRQ 计数增加也不能证明保存帧恢复或报文处理正确。
