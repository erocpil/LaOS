# 内存教程

英文原文：[Memory tutorial](memory-tutor.md)。

内存代码需要分别回答物理页归谁所有、哪个虚拟地址映射该页，以及用户任务预留了哪些区间。PMM、VMM 与 VMA 跟踪分别承担这些职责。

## 1. 分析物理分配

阅读 `kernel/pmm.c` 的 `pmm_alloc()` 及位图扫描，再查找先使用 `phys_to_virt()` 后写入页面的调用者。转换提供 CPU 可访问别名，不改变所有权。

对新页面，明确初始化者与最终调用 `pmm_free()` 的位置，不能仅凭分配器名称推断清零。

## 2. 遍历一个地址转换

使用 `kernel/vmm.c` 的 `vmm_get_phys()` 分析 x86_64 四级页表。每级索引选择九个地址位，普通页保留十二位字节偏移。先检查大页分支，不能假定所有遍历都到达 4 KiB 叶节点。

比较 `vmm_map()` 与 `vmm_map_user()` 的根参数，前者接受虚拟指针，后者接受物理根地址。地址类型错误可能在切换地址空间后才表现出来，容易被误判为调度故障。

## 3. 预留区间但不分配数据页

`user/main.c` 已包含以下使用模式：

```c
char *buf = mmap(8192, PROT_READ | PROT_WRITE, MAP_LAZY);
if (!buf)
    exit(1);
buf[0] = 'A';
buf[4096] = 'B';
munmap((unsigned long)buf, 8192);
```

mmap 后，一个 VMA 覆盖两页。每页首次写入因缺少转换而触发异常，处理程序分配页面并重试指令。示例先写后读，因为当前匿名分配不保证内容为零。

## 4. 反向分析释放

阅读 `kernel/arch/x86_64/syscall.c` 的 `do_munmap()`：定位精确 VMA，逐页查询并解除映射，释放物理存储，最后移除 VMA。未访问的惰性页没有对应物理分配。

再比较分配部分页面后失败的立即 mmap。当前失败返回没有执行对应的完整撤销，这是后续内存审查的重要区别。

## 5. 检查现有验证依据

```sh
make test-x86_64-multiuser
make test-x86_64-smp-tlb
```

在多用户日志中定位 `[P4-4] demand paging OK` 及第二页消息。目标本身统计用户完成标志，分析按需分页时还须检查中间输出。

512 MiB `MAP_LAZY` 请求预留虚拟区间，不访问全部页面。成功或失败均不能单独作为物理 OOM 测试；QEMU 内存大小与虚拟区间可用性是不同约束。

## 6. 练习：计算两页的状态

描述 mmap 后、各次写入后及 munmap 后的状态，分别统计 VMA 与用户数据页，并将页表页作为第三类分配。说明成功 mmap 返回为何不能直接推断任务占用的物理页数。

后续阅读：[内存架构](memory-arch-zh.md)与 [第 5 章：用户态](../../book/05-user-mode-zh.md)。

## 7. 练习：区分映射可见性与页面所有权

针对一个惰性页面，分别记录缺页和解除映射前后的 PMM 所有者、VMA 记录、页表项、TLB 状态以及 DMA/软件引用，并说明哪一个事件允许 PMM 复用页面。PTE 被清除不能单独证明所有 CPU 都已丢弃旧转换。
