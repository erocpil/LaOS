# 内存架构

英文原文：[Memory architecture](memory-arch.md)。

## 适用范围与所有权

LaOS 将物理分配、页表操作、内核堆分配及用户虚拟区间跟踪分开。本文说明当前 x86_64 路径，不表示已经实现完整 POSIX 虚拟内存子系统。

| 组件 | 管理内容 | 不提供的保证 |
| --- | --- | --- |
| `kernel/pmm.c` | 物理页位图与统计 | 虚拟映射及页面清零 |
| `kernel/vmm.c` | 页表构造与更新 | 用户区间策略 |
| `kernel/heap.c` | 内核分配块 | 用户分配生命周期 |
| `kernel/vma.c` | 每线程有序虚拟区间 | 实际物理页分配 |
| `kernel/arch/x86_64/page_fault.c` | 用户故障分类与按需映射 | 写时复制 |
| `kernel/arch/x86_64/syscall.c` | mmap/munmap 策略 | 通用映射事务 |

## 物理页与地址类型

PMM 初始位图标记为已占用，释放可用内存映射区域，同时保留自身位图及受保护区间。分配在全局 IRQ 安全锁下执行首次适配扫描。`pmm_alloc_pages()` 请求连续页，不提供分散聚集分配。

`pmm_alloc()` 返回编码为指针的物理地址，不清零页面。需要初始化数据的调用者应通过有效内核映射清零，再发布该页。

| 值或接口 | 地址类型 |
| --- | --- |
| `kernel_pml4` | 根页表的内核虚拟指针 |
| `thread->pml4_phys` | 物理根地址 |
| `vmm_map()`、`vmm_unmap()` 根参数 | 内核虚拟指针 |
| `vmm_map_user()` 根参数 | 物理地址 |
| `vmm_get_phys()` 根参数 | 物理地址 |
| `phys_to_virt()` | 物理地址转换为 HHDM 别名 |

`virt_to_phys()` 仅减去 HHDM 偏移，不遍历页表，不能用于任意堆、模块或用户虚拟地址。

地址类型规则同时也是所有权规则：

```text
PMM 分配物理页 -> 调用者通过内核别名初始化
                -> VMM 发布页表转换
                -> CPU/用户代码访问映射地址
                -> 解除映射/失效 -> PMM 才能回收页面
```

DMA 描述符中的物理地址不是用户虚拟地址，也不一定等于任意内核指针的数值。页表、DMA 设备或软件队列仍然引用页面时，不能将该页归还 PMM。

## 内核与用户页表根

BSP 的 `vmm_init()` 分配根页表，按需保留已有低地址条目并复制 Limine 高半区条目。复制条目引用的下级映射继续共享，AP 采用该内核根。

内核预分配高半区根条目，使已经复制条目的用户页表仍能观察后续下级内核映射。`vmm_create_user_pml4()` 清空新根并从 `kernel_pml4` 复制条目 256 至 511，低半区用于用户映射。

这是映射结构共享，不是复制每个物理页。销毁应回收独立用户映射，不能回收共享内核子树。嵌入式启动示例直接使用内核根，见 [用户态架构](../user/user-arch-zh.md)。

## VMA 与实际页面

VMA 在每线程有序链表中记录 `[start, end)`、保护及映射标志，用于判断区间是否预留；页表遍历判断某页当前是否具有转换。

```text
不使用 MAP_LAZY：预留 VMA -> 分配并映射页面
使用 MAP_LAZY：  预留 VMA -> 返回虚拟地址
                           -> 首次访问异常 -> 分配并映射页面
```

syscall ABI 为 `mmap(length, prot, flags)`，不接受地址或文件描述符。存在 `MAP_FIXED` 等常量不表示支持 Linux 映射语义。

x86_64 munmap 要求舍入后的区间完整匹配一个 VMA。`vma_free()` 同样要求精确匹配，两者都不会拆分 VMA 以释放任意子区间。

## 按需缺页路径

处理程序读取 CR2，区分用户与内核异常，并查找当前线程 VMA。VMA 内的用户缺失页异常会分配页面，并根据 VMA 设置用户、可写及 NX 标志。权限异常终止用户线程，内核异常进入诊断。

当前边界包括：

- 按需页未显式清零，PMM 也不保证清零。
- 分配缺失页面之前，未完整核对访问与 `PROT_READ` 的关系。
- 立即 mmap 失败返回零，但不完整撤销已建立映射和 VMA。
- 区间舍入及分配失败路径尚未全面加固。
- 无 COW、交换、页缓存或共享地址空间引用模型。

这些限制不能作为应用可依赖行为。在将此教学路径用于不可信程序隔离之前，必须解决相应问题。

缺页路径应分开处理三个决定：

1. 判断异常来自用户还是内核，并读取故障地址；
2. 查找精确 VMA，推导页面应具备的权限；
3. 分配、初始化并发布页表转换，或终止任务。

修复不存在页面异常不等于接受保护异常。当前权限检查和回滚检查不完整，因此它们是正确性边界，而不只是性能限制。

## 映射更新与 SMP

VMM 使用 `vmm_lock` 串行化更新。解除映射清除转换并执行本地失效，包装接口在释放锁后请求远程 TLB 失效。修改回收逻辑时，应同时检查更新和 IPI 路径；发送中断与证明相关 CPU 全部完成是不同事件。

现有重新映射测试验证重复跨 CPU 可见性，不证明任意地址空间销毁或所有交错下的通用页面复用协议。

TLB 协议具有两个完成点：

```text
更新页表 -> 失效本地转换
          -> 请求远程失效
          -> 远程处理程序到达
          -> 失效远程转换
          -> 返回到可以复用页面的代码
```

在远程完成点之前复用页面，可能使其他 CPU 继续使用旧转换。重新映射测试只验证该协议的有界实例，不构成所有地址空间的通用拆除屏障。

## 验证

```sh
make test-x86_64
make test-x86_64-smp-tlb
make test-x86_64-multiuser
```

除目标退出状态外，还须检查 VMA 单元结果和按需分页输出。多用户目标统计完成消息，不检查匿名页面清零或完整分配回滚。阅读练习见 [内存教程](memory-tutor-zh.md)。

验证结果应按层解释：VMA 测试覆盖区间记录，按需分页标志覆盖一次异常与重试，SMP 重新映射测试覆盖有界 TLB 可见性序列。它们均不证明清零、COW、交换、完整 mmap 回滚或任意页面复用同步。
