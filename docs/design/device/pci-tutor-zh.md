# PCI 教程

英文原文：[PCI tutorial](pci-tutor.md)。

PCI 设备发现用于确定设备是否存在及其控制寄存器的位置，驱动初始化则负责配置设备的运行方式。阅读本教程时，可结合 [PCI 架构](pci-arch-zh.md)核对接口约束。

## 1. BDF 与配置空间寻址

对于总线 0、设备 3、功能 0，寄存器 `0x10` 的 ECAM 偏移为：

```text
(0 << 20) + (3 << 15) + (0 << 12) + 0x10 = 0x18010
```

该偏移应加到已映射的 ECAM 基址上，而非设备 BAR 地址。ECAM 包含配置寄存器；BAR 描述其他设备资源，例如网卡的 MMIO 寄存器区域。

## 2. 枚举流程

阅读 `kernel/pci.c` 中的 `pci_scan_all_buses()`，依次定位设备缺失判断、多功能判断、BAR 解析及向 `g_pci_devices` 插入记录的操作，再查找 e1000 对厂商及设备标识 `8086:100e` 的匹配过程。

设备已经出现在枚举列表中，驱动初始化仍可能失败。枚举过程不负责分配描述符环、启用 DMA，也不保证中断路由可用。

对每个已发现设备保留五项记录：BDF、类别码、解析后的 BAR 地址/属性、command 寄存器位以及所选中断路由。不要用一条“发现 PCI 设备”日志替代这些信息。

## 3. 地址类型

对同一设备，分别确认配置空间地址、BAR 物理地址以及访问 BAR 所用的内核虚拟映射。对 DMA 缓冲区，还须确认写入描述符的物理地址。这些地址可通过映射关联，但不能相互替代。

## 4. 验证真实 PCI 传输路径

```sh
make test-x86_64-lafs
```

检查 PCI 发现、virtio 队列初始化以及真实 LaFS 挂载和读取标志。内存中的 LaFS 单元测试数据可以在没有 PCI 磁盘的情况下通过；该集成目标则要求实际传输路径参与验证。

## 5. 单独验证中断

能力链表中的 MSI 条目仅表示设备提供 MSI 功能，不表示 LaOS 已经启用该功能或安装了有效处理程序。对于 x86_64 e1000，应检查 `pci_enable_intx()` 和回调注册路径。

后续步骤见 [e1000 教程](e1000-tutor-zh.md)。设备发现成功但报文处理失败时，应分别保留 BDF、BAR、命令寄存器状态及所选中断路由，作为定位依据。

在 ARM64 上，应通过平台 ECAM 路径重复该练习，并区分 MSI 选择与 INTx 回退；在 x86_64 上，应将可加载 e1000 模块的 INTx 注册与 PCI 能力发现分开检查。
