# e1000 教程

英文原文：[e1000 tutorial](e1000-tutor.md)。

本教程沿报文缓冲区的处理过程说明 CPU 与设备之间的交互。前置内容见 [PCI 教程](pci-tutor-zh.md)，描述符环与工作线程的所有权约束见 [e1000 架构](e1000-arch-zh.md)。

## 1. 设备发现

默认模块配置将 e1000 加载到 CPU 2。阅读 `conf/task.conf` 中的任务记录，再检查 `module/e1000.c` 中的 `main()` 和 `e1000_init()`。不存在匹配的 PCI 设备时，初始化不会进入描述符环准备阶段。

`make test-x86_64` 使用 `-net none`。该冒烟测试通过不能证明 e1000 接收、发送或 INTx 投递正常。

## 2. QEMU 配置

如需进行交互式设备发现实验，且不创建主机 TAP 接口，可执行：

```sh
make run HEADLESS=1 QEMU_NET='-netdev user,id=u1 -device e1000,netdev=u1,mac=52:54:00:12:34:56'
```

该命令使用 QEMU 用户网络后端附加网卡，适合观察设备枚举和初始化，但不能复现项目基于 TAP 的流量实验，也不能据此确认端到端网络功能。在无图形串口控制台中，按 Ctrl-a x 可退出 QEMU。

对于 ARM64，应区分 direct/Limine 内核路径中的内建初始化与 x86_64 的可加载模块路径。共享驱动函数不表示两条路径具有相同的 IRQ 路由或测试覆盖。

现有 TAP 配置与主机清理命令见 [入门指南](../../getting-started.md)。该配置会修改主机网络，仅在选用相应实验时需要。

## 3. 接收描述符处理过程

阅读 `e1000_init_rx_ring()`，确认 CPU 使用的环指针、写入硬件的物理基址以及某个槽位对应的接收缓冲区。随后沿轮询循环检查该槽位，直到观察到 DD 并推进尾指针。

对于批量模式，检查 `e1000_rx_batch_release()`。对于缓冲区替换模式，应确认原缓冲区交给软件消费者之前，替换缓冲区已经到位。在后一种模式中，归还描述符和释放已接收报文属于两个独立操作。

为每一步写下对象的所有者：

```text
描述符 -> 设备
已完成缓冲区 -> 批量数组/队列消费者
替换缓冲区 -> 完成 DMA 准备后交给设备
释放缓冲区 -> 空闲池或分配器
```

如果同一缓冲区同时出现在两个所有权列中，说明该转换不安全。

## 4. 中断通知与报文处理

检查 INTx 初始化消息。在有适当入站流量时，还可观察输出次数受限的 `[e1000] IRQ` 诊断消息。处理程序读取 ICR 并记录待处理事件，不负责解析报文。

如果中断已到达而处理停滞，应检查所选 `g_rx_mode`、描述符 DD 状态、软件队列和缓冲池。如果没有中断，应先检查网卡附加、INTx 启用、中断掩码和流量情况，再判断是否需要修改调度代码。

应将 `e1000_irq_handler()` 与 `e1000_wait_rx_event()` 一起阅读。处理程序只记录有界通知，描述符消费仍由工作线程负责；IRQ 日志是中间证据，不等于报文处理成功。

## 5. 练习：分析 TX 完成条件

沿 `e1000_send_packet()` 检查 `tx_lock` 获取、数据复制、描述符发布、尾指针更新和完成轮询。定位超时返回路径，并说明调用者为何不能将该结果计为成功发送。

当前示例包含报文辅助接口，但原始帧交换成功不表示已经支持套接字或 TCP。与存储路径的比较见 [第 6 章：设备](../../book/06-devices-zh.md)。

## 6. 验证清单

每次实验分别记录：

1. PCI 匹配、BAR 映射和总线主控启用；
2. 复位、MAC 读取和描述符环分配；
3. 中断原因投递和待处理工作线程唤醒；
4. DD 状态变化和描述符尾指针更新；
5. 报文消费、缓冲区释放和 TX 完成。

`make test-x86_64` 由于禁用网络，不能单独证明数据面。数据面验证应使用附加网卡实验，并将 TX 超时视为失败，而不是成功发送。
