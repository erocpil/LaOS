# PCI 架构

英文原文：[PCI architecture](pci-arch.md)。

## 适用范围与源码分工

PCI 层负责发现设备功能，并向驱动提供配置空间访问接口。共享枚举代码服务于 x86_64 的 ACPI/MCFG 路径以及由平台启动路径提供 ECAM 基址的 ARM64 路径。该实现主要面向 QEMU 验证，尚未提供通用 PCI 资源管理机制。

| 文件 | 职责 |
| --- | --- |
| `kernel/arch/x86_64/main.c`、`kernel/arch/aarch64/init_common.c` | 获取 ECAM 信息并安排 PCI 初始化顺序 |
| `kernel/arch/x86_64/acpi.c` | 提供 ACPI 表访问支持 |
| `kernel/pci.c`、`kernel/pci.h` | ECAM 访问、设备枚举以及 BAR 和能力信息解析 |
| `module/e1000.c` | e1000 设备选择与初始化 |
| `kernel/arch/x86_64/virtio_pci.c` | virtio PCI 传输层发现 |

## 配置空间访问

`pcie_init()` 将 x86_64 ECAM 窗口映射至 `PCIE_VIRT_BASE`，页表属性采用禁用缓存和写穿透。配置寄存器地址按下式计算：

```text
ECAM 虚拟基址 + (bus << 20) + (device << 15) + (function << 12) + offset
```

`pci_read8/16/32()` 及对应写接口分别执行不同宽度的寄存器访问。访问宽度属于接口约束。例如，更新 16 位命令寄存器时，不应误写相邻状态寄存器中具有写 1 清零语义的位。

当前 ECAM 映射与固定寻址方式尚未支持任意多段 MCFG 布局。扩展总线范围时，还须核对起始总线编号在地址计算中的处理方式。

配置空间访问属于设备发现，不等于驱动启用。安全的启用顺序是：

```text
读取厂商/设备标识 -> 解析类别和 BAR -> 选择驱动
                  -> 启用内存/IO 及总线主控
                  -> 建立 BAR 映射和 DMA 状态
                  -> 选择并启用中断路由
```

共享辅助接口不会将上述顺序作为事务自动回滚。调用者启用 command 位或写入 BAR 后，须负责随后分配资源的失败清理。

## 设备枚举与元数据

`pci_scan_all_buses()` 遍历已配置的总线范围，每条总线包含 32 个设备槽位，每个设备最多包含 8 个功能。厂商 ID 为 `0xffff` 表示该槽位不存在设备；功能 0 的多功能标志决定是否继续探测其余功能。

设备记录保存 BDF、设备标识、类别、BAR、中断及能力信息，并通过 `g_pci_devices` 对外提供。驱动可使用 `pci_find_device()` 查找设备。

BAR 解析需要分离属性位和地址，并处理占用两个槽位的 64 位内存 BAR。解析得到的 BAR 是设备资源地址，只有建立有效映射后才能作为 CPU 访问对象。枚举成功也不表示驱动已经启用内存地址译码或总线主控。

## 中断与驱动启用

传统 INTx 路由与 MSI 能力信息分别维护。`pci_enable_intx()` 启用已记录的传统中断路由。发现 MSI 能力并不表示中断向量分配、投递和分发均已实现。当前 x86_64 e1000 路径采用 INTx。

e1000 仍以可加载模块运行。启动代码缓存其中断向量，模块向 IDT 层注册处理回调。virtio-blk 则在启动期间初始化传输层，并通过轮询处理队列。尽管头文件定义了驱动类型，这两条路径均不足以构成完整的动态绑定与解绑框架。

## 验证与限制

中断辅助接口具有不同契约：

| 接口 | 作用 | 不提供的保证 |
| --- | --- | --- |
| `pci_enable_intx()` | 启用传统 command 位并记录架构使用的路由 | 设备处理程序已经安装 |
| `pci_enable_msi()` | 配置设备支持的 MSI 能力并在 command 中启用 MSI | 平台会将向量投递到预期处理程序 |
| 驱动回调注册 | 将设备原因连接到内核回调 | 设备原因已经启用或回调会清空设备 |

当前 e1000 在 x86_64 使用 INTx，在 ARM64 优先尝试 MSI，失败后回退到 INTx。该策略属于驱动与架构集成，不能由能力发现单独推出。

```sh
make test-x86_64-lafs
```

该目标要求真实 virtio-blk/LaFS 路径产生验证结果，涵盖 PCI 传输层发现。普通启动测试使用 `-net none`，不能验证 e1000 中断或接收路径。相关独立实验见 [e1000 教程](e1000-tutor-zh.md)。

当前测试未覆盖热插拔、跨桥的通用 BAR 分配、广泛的固件兼容性和任意中断拓扑。[PCI 教程](pci-tutor-zh.md)分别说明设备发现与设备运行的验证方法。

最小 PCI 证据应保留 BDF、原始 BAR 值、解析后的 BAR 属性、command 寄存器状态及所选中断路由。设备出现在列表中而没有这些后续信息，只能证明枚举成功。
