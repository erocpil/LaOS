## 2.1 同一物理页的不同地址表示

同一物理页可以表示为 PMM 返回的物理地址、内核使用的 HHDM 指针，以及用户任务使用的低地址虚拟指针。这些值可指向相同字节，但用途不同。

```text
PMM 物理页 <--- 用户页表项 <--- 用户虚拟地址
     |
     +--- phys_to_virt ---> 内核直接映射指针
```

增加映射或加上 HHDM 偏移不会产生新的物理分配。反之，移除一个映射也不能证明对该页的其他引用全部消失。

## 2.2 PMM 管理页面可用性

`kernel/pmm.c` 使用全局 IRQ 安全锁保护位图。初始化时将页面标记为不可用，再释放适当的可用区域，同时保留自身元数据。首次适配扫描查找单页或连续页区间。

PMM 不清零分配结果。ELF 加载器复制文件数据之前，会显式清零段内存；当前按需分配没有同样的清零保证。初始化属于调用者策略，而非物理分配器的隐含属性。

## 2.3 VMM 建立地址转换

`kernel/vmm.c` 遍历 x86_64 四级页表，并单独处理大页情形。映射建立地址转换，权限控制用户访问、写入和指令获取。

`vmm_map()` 接受内核虚拟页表根指针，`vmm_map_user()` 接受物理页表根地址。两者都采用指针形式的 C 类型，使用时必须核对地址类型，不能仅凭编译通过判断正确性。

用户页表根复制内核高半区条目。用户条目独立，但其引用的内核子树仍然共享；销毁遍历必须遵守这一归属边界。

## 2.4 VMA 记录虚拟区间预留

VMA 保存半开区间及保护标志。使用 `MAP_LAZY` 时，mmap 建立记录后返回，不分配对应数据页。

首次访问触发缺页异常。地址属于用户 VMA 时，处理程序可分配物理页、安装映射并重试指令。指令恢复过程见 [第 3 章](03-interrupt-zh.md)。

当前 munmap 要求完整匹配一个 VMA，不支持局部区间拆分、COW 或文件映射 API。立即分配失败后，也尚未完整回滚已映射页面和已插入 VMA。

## 2.5 回收还涉及缓存的地址转换

页表变化后，CPU 可能仍保留旧转换，因此映射更新还需要本地 TLB 失效和跨 CPU 失效请求。保护页表字节的锁不会自动清除其他 CPU 的缓存转换。

审查页面复用时，应分别确认谁仍持有指针、谁仍可通过旧虚拟地址访问该页。这是两类不同的访问风险。

## 实验：比较预留与实际分配

```sh
make test-x86_64-multiuser
make test-x86_64-smp-tlb
```

结合第一项测试日志阅读 `user/main.c`。两页惰性映射分别访问两页，应分别计算一个 VMA 与零、一、两个实际数据页；页表页属于额外分配。

同一程序中的 512 MiB 惰性申请不会耗尽物理内存。当前 mmap 搜索窗口仅为 `0x04000000` 至 `0x10000000`，虚拟区间大小已足以解释该申请失败。
