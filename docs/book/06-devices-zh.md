## 6.1 设备发现定位访问接口

PCI ECAM 通过总线、设备和功能编号定位配置寄存器。枚举读取标识与资源信息并记录设备，供驱动查找。BAR 描述 MMIO 寄存器区等资源，与 ECAM 配置地址不同。

设备出现在列表中仅表示发现成功。驱动仍须启用地址译码、按需启用总线主控、映射寄存器，并准备设备可使用的数据结构。

## 6.2 DMA 引入硬件访问者

e1000 无须执行 CPU 的 C 代码即可读写描述符环和报文缓冲区。CPU 锁协调软件调用者；硬件所有权还取决于描述符状态及头尾位置。

通知设备之前，驱动必须完成缓冲区和描述符填充。接收时必须确认完成后才能消费报文字节，重新开放槽位之前须提供可用缓冲区。

描述符中的物理地址与软件虚拟指针不能混用。缓存维护和顺序保证也不能由硬件字段上的 `volatile` 替代。

## 6.3 中断通知与工作线程消费

x86_64 e1000 IRQ 回调记录 ICR 原因，并可通知工作线程；所选接收循环负责消费描述符。不同轮询和工作线程模式具有不同的缓冲区生命周期，仅有中断计数不能证明报文处理正确。

e1000 在该路径中为可加载模块。回调必须指向已加载实例，实例生命周期必须覆盖硬件与工作线程引用。模块代码仍在内存中不等于存在安全卸载协议。

## 6.4 存储格式与传输层分离

```text
LaFS 文件读取 -> block_device 读取 -> virtio PCI 请求 -> QEMU 磁盘
```

LaFS 解释文件系统，块设备注册表分发扇区读取，virtio 传输层提交描述符并处理完成。分层使解析器可以在无磁盘条件下使用内存测试数据验证。

解析测试通过不能证明真实设备 I/O 正常。LaFS 集成目标在启动测试重置模拟注册表之后，检查真实 virtio-blk LaFS 挂载标志。启动流程还会尝试读取 `/etc/motd`，但该目标不对文件内容作断言。

当前 LaFS 只读，virtio-blk 使用轮询，块设备注册表选择最后注册设备，没有通用设备命名空间。
