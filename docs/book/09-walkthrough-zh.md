## 9.1 选择范围明确的问题

本章分析配置中的用户任务如何访问惰性页面、休眠并返回用户态。该问题跨越多个子系统，但有明确路径和现有测试配置。

从 `conf/task-x86_64-multiuser.conf` 开始。该配置在 CPU 0 建立三个用户任务。还须阅读目标配方，确认 QEMU 内存、CPU 数、超时和完成断言。

## 9.2 分析构造阶段

```text
任务配置 -> create_elf_process
         -> 独立用户页表根、ELF 段与参数栈
         -> 线程内核栈与初始切换帧
         -> 入队 -> 首次进入 ring 3
```

为每个箭头定位消费前一步状态的函数。嵌入式启动示例不采用同一个私有页表根构造器，应单独分析。

## 9.3 分析一次惰性写入

`user/main.c` 申请 8192 字节惰性区间。首次访问之前，定位 VMA 并说明为何尚不需要数据页，再沿写入检查向量 14、VMA 查找、分配和映射。

修复后的异常返回重试用户指令。后续 `write()` 通过 syscall 打印数据，不复用缺页异常的中断帧。两种返回路径可以连续发生，但保存布局不能互换。

## 9.4 分析挂起与完成

沿休眠包装进入 `schedule_timeout()`，说明其他用户任务运行时，哪一个内核栈保存未完成系统调用。恢复后，处理程序更新保存的 RAX，并通过 `sysret` 返回。

程序先输出完成标志，再调用 exit。这是两个事件；测试统计前者，全部资源销毁仍需要额外验证。

## 实验：收集相关验证结果

```sh
bash script/check_doc_links.sh
make test-task-conf-v1
make test-x86_64-multiuser
```

第一项检查文档引用，第二项检查已提交配置语法，第三项执行所选内核场景。两个主机侧检查都不执行内核解析器，也不验证寄存器恢复。

多个 QEMU 目标复用 `build/serial.log`。比较结果前应保留相关日志，避免后续运行覆盖先前依据。

## 9.5 按故障所在层次检查

| 观察结果 | 优先检查 |
| --- | --- |
| 构建失败 | 编译与链接输出、生成偏移依赖 |
| 没有内核输出 | QEMU 启动错误、ISO 内容与引导交接 |
| 用户 ELF 未输出标志 | 任务配置、加载器与首次入口帧 |
| 惰性访问导致终止 | CR2、错误码、VMA 和页表标志 |
| 休眠后停止运行 | 状态、唤醒 tick、运行队列与中断进展 |
| 完成消息数量不足 | 各任务输出、超时与先前异常 |

第一个缺失的预期结果用于缩小范围，不证明前一个子系统就是根因。修改代码之前应检查该边界的状态。

## 9.6 形成可复核的结论

报告应记录分支或提交、配置、命令、断言结果及未覆盖限制。多个完成消息支持重复用户执行的结论，但不能证明 fork、匿名内存清零、畸形输入安全或退出无泄漏。
