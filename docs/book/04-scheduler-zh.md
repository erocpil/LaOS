## 4.1 调度首先判断运行资格

每 CPU 维护 64 个优先级桶及非空桶位图。优先级 0 最高，默认值为 32。位于桶中的线程不一定可运行，BLOCKED 和 SLEEPING 节点也仍然链接在队列中。

`pick_next()` 从优先级最高的非空桶开始检查状态，还将候选者与当前 RUNNING 线程比较，因为 READY 扫描会跳过当前线程。普通任务均不能运行时，选择 idle。

## 4.2 严格优先级与同级轮转

优先级决定桶之间的选择，轮转决定同级可运行线程的顺序。持续运行的优先级 8 负载可能无限期阻止优先级 32 任务运行；桶 8 内的轮转不会消除这一饥饿问题。

因此，`yield()` 不保证所有其他任务得到运行机会。休眠或阻塞可以改变运行资格，单纯让出 CPU 不一定使低优先级任务成为首选。

## 4.3 切换恢复续执行上下文

`__schedule()` 更新状态并选定下一任务；地址空间切换建立所需页表根；`switch_to()` 保存当前内核栈指针、FPU 状态等续执行上下文，再恢复另一个上下文。

恢复后的返回地址可能指向此前挂起的调度调用。新线程则通过构造的保存帧进入首次运行跳板。`ret_from_fork` 是该跳板名称，并不表示实现了 fork 系统调用。

汇编使用的结构体偏移属于 C 与汇编之间的接口。扩展 TCB 后未重新生成偏移，会在保存 FPU 状态时破坏其他字段，因此增量构建依赖也是正确性要求。

## 4.4 唤醒必须通知目标 CPU

入队先发布节点，再请求重调度。远程请求还发送 IPI，使目标 CPU 无须等待无关事件。本地请求直接设置待处理标志。

唤醒互斥锁等待者不同于创建新任务：其运行队列节点已经存在，重复插入会破坏链表归属。

## 4.5 优先级继承改变有效优先级桶

高优先级等待者可向低优先级互斥锁所有者捐赠优先级。有效优先级变化时，所有者节点必须迁移到对应桶；解锁撤销捐赠后，节点可能再次迁移。

当前为单跳继承，使用计数聚合多个已持有互斥锁的贡献，不支持沿任意阻塞所有者链传播。锁和生命周期约束见 [第 7 章](07-synchronization-zh.md)。

## 实验：将执行顺序与策略对应

```sh
make test-x86_64
make test-x86_64-sched-stress
```

检查 `priority` 测试的高、同级及低优先级顺序阶段和反转阶段，定位所有者被提升后仍留在原桶时会失败的断言。该确定性依据与压力测试中的更广泛调度活动应分别解释。
