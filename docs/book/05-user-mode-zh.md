## 5.1 构造执行环境

配置中的 type-3 任务通过 `create_elf_process()` 分配 TCB 和用户页表根，加载 ELF 段，并建立用户栈与内核栈。独立低地址映射保存用户内存，共享高地址映射使内核代码在特权转换之后仍可访问。

用户栈中的参数指针采用用户虚拟地址。内核通过自身映射写入这些值，不能将 HHDM 指针存入 `argv`，否则用户代码将获得错误的地址类型。

启动文件另有使用内核页表根的嵌入式 ELF 示例。分析私有地址空间时，应沿配置任务路径阅读，不应将两种构造方式合并描述。

## 5.2 首次进入与系统调用返回

首次进入时，架构桩函数用 ELF 入口、用户栈和 ring-3 选择子构造 `iretq` 帧。`user/crt0.s` 中的 `_start` 读取参数布局并调用 `main()`。

后续系统调用需要恢复实际的用户续执行状态。硬件将返回 RIP 写入 RCX、标志写入 R11，再跳转到 LSTAR 指定入口。硬件不会自动选择线程内核栈，汇编必须显式完成该操作。

## 5.3 建立 syscall 帧后再启用中断

入口切换 GS，暂存用户 RSP，选择当前线程内核栈并保存 syscall 帧。18 个槽位包含除硬件覆盖的 RCX/R11 之外的通用寄存器，以及返回 RIP、选择子、标志和 RSP。

精确顺序见 [保存帧布局](../design/user/user-arch-zh.md#完整-syscall-帧)。R12–R15 均有独立槽位；RCX/R11 提供的返回状态由 RIP 和 RFLAGS 表示，不是指令执行前原寄存器内容的快照。

保存帧完整建立后，C 代码才启用中断。此后发生抢占，也能保留用户返回状态。

## 5.4 分发与返回

分发器从保存的 RAX 读取调用号，从其他保存寄存器读取参数，支持 write、yield、mmap、munmap、sleep 和 exit。该 ABI 为项目专用接口，不提供 Linux 调用号兼容或完整 POSIX 行为。

可返回调用由 C 将结果写入保存的 RAX，关闭中断并处理待执行重调度，然后由汇编恢复状态并执行 `sysret`。休眠中的系统调用在其他任务运行后，仍可沿同一路径恢复。

## 5.5 保存帧与进程模型

复制 syscall 帧不会复制其引用的页面。fork 还需要子地址空间、所有权规则、子任务首次运行路径、不同的父子返回值，以及部分失败时的清理。等待子任务和收集状态又需要额外生命周期管理。

当前没有 fork 系统调用，`ret_from_fork` 用于首次线程入口。退出请求日志也不能证明存在父任务等待机制，或证明资源回收已通过验证。

## 实验：分析三个用户任务

```sh
make test-x86_64-multiuser
```

配置在单 CPU 上建立三个用户任务。检查加载、休眠或让出 CPU、惰性页面访问和完成输出。历史完成标志仍写作 `EL0`，但 x86_64 实际使用 ring 3。

目标在 `exit()` 之前统计该消息，不检查所有寄存器哨兵值，也不证明最终页面回收。这些性质需要独立测试。
