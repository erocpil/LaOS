## 1.1 引导交接提供初始执行状态

固件与 Limine 加载内核 ELF，并建立进入内核所需的执行状态。LaOS 从 `kernel/arch/x86_64/main.c` 中的 `kmain()` 开始运行。此时已有映射和可用栈，但内核仍须确定物理页归属、建立中断处理机制，并决定哪些任务可以运行。

启动信息通过静态 Limine 请求结构中的响应指针提供。`check_bootloader()` 检查这些响应，而非解析通过 RDI 传入的常规启动信息参数。

## 1.2 可访问内存与可分配内存

HHDM 响应提供直接映射偏移。初始化偏移后，内核可以转换地址。内存映射适配层随后复制 PMM 所需的内存区域描述。

PMM 位图判断物理页是否可分配，引导程序建立的映射则决定 CPU 能否访问该页。某页已经映射，不表示它可以分配；占用已保留的页面仍会破坏原所有者的数据。

PMM 初始化后，VMM 建立内核页表根，堆分配器再提供小于页面粒度的分配。这一顺序为每 CPU 数据、模块和线程准备内存。

## 1.3 建立中断运行条件

GS 状态标识当前 CPU。GDT/TSS 提供段与栈状态，IDT 提供中断入口，LAPIC 和 I/O APIC 将中断源连接到相应入口。

BSP 在内存初始化之前建立早期描述符状态，在映射可用后配置中断硬件。阅读实际调用顺序时，应分别检查这些依赖，不能将所有中断初始化视为单一步骤。

## 1.4 初始化其他 CPU

`start_smp()` 通过 Limine 的 `goto_address` 指定 AP 入口。AP 初始化本地寄存器及每 CPU 上下文，采用内核页表根，并参与 CPU 上线屏障。

共享 IDT 表不免除每 CPU 加载 IDTR 的要求；BSP 上配置 syscall MSR 也不会自动配置 AP。逻辑 CPU 编号还须与硬件 LAPIC ID 区分。

## 1.5 构造任务与开始执行

启动路径先运行早期单元式测试、枚举 PCI 设备并尝试真实 virtio/LaFS 路径。任务配置负责构造模块和用户任务，注册式自测试另有准备与执行阶段。

`task_run()` 释放已配置任务后返回。后续执行由调度调用和中断返回时的抢占驱动。主线程最终启动监视器并反复休眠，运行期工作并不全部封装在一个启动函数中。

## 实验：定位初始化依据

```sh
make test-x86_64
```

在串口日志中定位页表根切换、CPU 上线、命名自测试结果和 `LaOS is running`，并查找各消息的输出函数。AP 消息顺序可能变化，应比较初始化依赖，而非要求固定交错顺序。

启动标志不能单独证明用户任务退出或真实磁盘 I/O 正常，这些行为需要各自的验证依据。
