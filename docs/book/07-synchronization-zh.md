## 7.1 明确所需保证

共享计数器、存在竞争的资源以及已从链表移除的节点，需要不同的同步保证。计数器可能需要原子更新；资源需要明确的所有权；节点则必须在旧读者仍持有引用期间保持有效。

| 机制 | 主要保证 | 关键约束 |
| --- | --- | --- |
| 原子操作 | 对共享状态执行单个受支持的原子操作 | 不自动维护跨多个字段的不变量 |
| 自旋锁 | 临界区互斥访问 | 持锁期间不得阻塞 |
| 互斥锁 | 独占所有权，等待者可以休眠 | 要求可调度上下文 |
| RCU | 发布和移除过程中的读者引用生命周期 | 写者仍须自行串行化 |

同步机制应根据所需保证选择，不能预设某一种原语在所有场景下都更快。

## 7.2 本地中断屏蔽的作用范围

`kernel/lock.h` 区分原始自旋锁、禁用抢占的自旋锁和保存中断状态的锁。如果同一 CPU 上的 IRQ 处理程序可能获取某个锁，被中断的持锁线程必须在持锁期间防止这类重入。

禁用本地中断不会阻止其他 CPU 访问对象。锁提供跨 CPU 互斥，保存的中断状态则用于控制本地重入。释放锁后应恢复原有中断状态，而非无条件启用中断。

## 7.3 阻塞等待与调度依赖

互斥锁等待者进入 BLOCKED 状态，使其他任务可以运行。慢获取路径在等待队列锁保护下再次检查所有权，避免快速获取失败至进入休眠之间的解锁事件被遗漏。

默认 raw 策略允许解锁后新到达线程抢先获取锁。handoff 策略将所有权保留给选定等待者。两者均采用优先级排序和单跳优先级捐赠，使高优先级线程等待时，锁所有者能够获得执行机会。

捐赠计数可以聚合多个互斥锁的贡献，但不会沿任意所有者依赖链传播。分析嵌套锁和最坏等待时间时，必须考虑这一限制。

## 7.4 节点移除与内存回收

写者从链表移除节点后，RCU 读者可能仍持有指向该节点的指针。写者必须等待旧读者结束访问，才能释放节点：

```text
初始化 -> 发布 -> 读者可能持有指针
          移除 -> synchronize_rcu -> 回收
```

发布顺序保证读者能观察到已经初始化的字段；宽限期保护对象生命周期。没有额外同步规则时，两者均不能保证任意并发字段更新安全。

LaOS 允许读者被抢占，同时跟踪已切出的读者和各 CPU 的静止状态。`synchronize_rcu()` 在线程上下文中等待。当前尚未实现 `call_rcu()` 回调队列；已有相关文档描述的是后续设计方案。

## 实验：验证执行顺序

```sh
make test-x86_64
make test-x86_64-rcu-stress
```

结合优先级反转测试，说明为何中等优先级任务不应在已被提升的所有者解锁之前运行。结合 RCU 发布及压力测试，分别分析初始化可见性与延迟回收。

作为源码阅读练习，在 `rcu_read_lock()` 保护范围内选择一个指针，确认其在对应解锁之前最后一次允许使用的位置，并说明为何将指针复制到局部变量不会延长所指对象的生命周期。
